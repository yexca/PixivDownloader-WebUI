## 关键设计与兼容性

- 新作品表示下载水位之后的未完成作品；pending只包含pending/remote_only文件，failed只包含失败页面，all包含范围内全部已同步文件。游标检查整个已知作品库，不靠简单改排序修补缺口。已有水位不自动重置；历史水位以下的未完成记录仍可通过pending/failed处理。
- Job领域模型维持原有终态：出现文件失败时任务为failed；options.result说明全部失败或部分失败。节点partial表示任务内已有成功成果；工作流partial也可表示前面已有完成节点、后续失败，不表示下载成功。失败信息和可重试性随接口返回。
- `force_rescan`保留旧的全量扫描/允许重新处理已同步文件行为；`full_download`也进行全量同步。pending-only及显式失败重试仍限定文件来源；only-new和其他筛选进一步约束范围。标签skip属于用户明确跳过，标签retry_failed不会把其他页面标成完成。
- 取消是协作式的：等待期间约每0.2秒检查，文件每个流块检查；正在阻塞的网络读取由超时界定。已获取的元数据快照会先写完整，再观察取消，避免只写最大ID后下一次增量漏掉下方作品。
- 支持单应用进程内并发。SQLite领取及文件路径锁避免重复和冲突；启动恢复会释放前一进程的领取记录。多个Uvicorn进程/共享数据库副本不在支持范围内，部署文档已明确。
- 022新增执行/调度领取表；023追加旧计划语义修复，历史SQL未修改。023保留触发状态、时间和历史；017之后用户编辑的定义保留并记录需要审查的日志，不从旧快照覆盖新设计。
- 既有无timezone计划保留UTC。新日/周/月计划使用所选IANA时区；DST缺失时刻前移经过缺口、重复时刻仅执行第一次；所有执行瞬间仍存UTC。

## 依赖审计与剩余事项

- React Router从7.18.1升级到7.18.4、Vite从6.4.3升级到6.4.4、PostCSS从8.5.16升级到8.5.29，其他升级保持原有主要依赖的兼容大版本。新增Vitest5用于实际行为测试。Router的相关告警仅涉及unstable RSC；该项目是浏览器SPA，同时已经升级到补丁版本。[上游说明](https://github.com/remix-run/react-router/security/advisories/GHSA-qwww-vcr4-c8h2)
- 前端完整audit仍有**8项（5 high、3 moderate）**，根源为Tailwind3的braces与postcss-selector-parser链路。它们处理本仓库构建时的glob/CSS；没有在请求中解析用户提供的glob/CSS，生产镜像只包含生成的静态资源。tailwindcss-animate归入实际使用它的devDependencies，未将构建工具标为浏览器运行依赖。生产依赖audit和sidecar audit均为**0**，没有忽略完整audit的剩余告警。[braces审计记录](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)、[PostCSS上游说明](https://github.com/postcss/postcss-selector-parser/security/advisories/GHSA-rj75-hqrm-r3gf)
- 自动清零会要求Tailwind4或强行替换不同大版本的内部解析器。此次没有做无关CSS框架迁移；完整消除这些构建告警需要另行决定是否迁移Tailwind4及其样式兼容范围。不应把不可信CSS/模式加入当前构建输入。
- 已在017之后修改的旧计划无法从快照判断新设计是否有意扩大/改变范围；如存在这类记录，需要对照其现有设计和旧动作决定是否手动调整。测试证明023不会覆盖后续编辑。此次未查询用户实际数据库来判断是否存在此类记录。
- 没有运行真实Pixiv端到端认证/下载，按要求使用模拟网络。锁文件固定应用依赖版本；Docker基础镜像、系统包和构建工具仍遵循上游供应，不声称整个镜像按字节可复现。

## 对现有数据的影响

最终回归使用临时数据库和下载目录，未修改用户数据库、配置和下载文件，也未读取或输出真实凭据。早期基线测试曾在resources/imports生成六个测试上传副本；后续已加入默认路径和环境隔离，保留这些已忽略的副本，没有删除数据库文件。Docker构建上下文现已排除全部数据库、导入目录、缓存和私有.env。新增的其他本地产物为开发虚拟环境、依赖、构建资源和独立验证镜像，没有部署或推送。

用户以后启动新版时才会应用022/023。迁移不删除下载/配置，不创建运行任务；既有任务和关联在启动恢复中保留。默认skip仍适用于已知完整文件；旧failed/downloading残片在显式重试时使用临时文件替换，原文件直到成功前保持不变。无法凭数据库识别的历史无记录残片不会擅自删除。

使用认证sidecar前，需要在私有.env配置新的随机token与VNC密码，并重新创建后端容器接收环境变量。设置文件仍以JSON为事实来源。升级前可按[Deployment](deployment.md)停服备份，远程访问使用SSH隧道。
